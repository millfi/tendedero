# Snapline — Windows版

[Tendedero](https://github.com/alejandrobujan/tendedero)を基にした、Rust / WinUI 3のスクリーンショット用の棚です。
Windows版は [millfi/tendedero](https://github.com/millfi/tendedero) のフォークで開発しています。
上流のコードのMITライセンスと著作権表示を保持し、名前とアイコンは独自のものにしています。
元のSwiftコードは `Sources/Tendedero` に残しています。

## 起動とビルド

Windows 11 x64、Rust 1.98以降のMSVCツールチェーン、Visual StudioのC++ビルドツールが必要です。
初回ビルドではCargoとNuGetから依存関係を取得します。アプリの実行中にネットワーク通信は行いません。

```powershell
cargo build --locked --release
.\target\release\snapline.exe
```

`windows-reactor-setup` がWindows App Runtime 2.4を実行ファイルと同じフォルダーに配置します。
EXEだけを移動せず、同梱のDLL・PRI・言語フォルダー・アイコンも一緒に配布してください。
インストーラーや管理者権限は不要です。

配布用フォルダーを作成するには：

```powershell
.\scripts\build-windows.ps1
# build\Snapline\snapline.exe
```

空き容量が少ない場合は、`-TargetDir C:\任意のビルド先` と `-OutputDir C:\任意の配布先` を指定できます。
開発用のDebugビルドの再起動は `scripts/run-windows.ps1`。このチェックアウトの実行ファイルを終了してから再ビルドします。
通常の利用では画像処理の速いReleaseビルドを使用してください。
`--data-dir <フォルダー>` は通常の保存先と分離した動作確認用です。

## 使い方

| 操作 | 動作 |
| --- | --- |
| Ctrl+Alt+T | 棚を表示／非表示 |
| Ctrl+Alt+S / 範囲を撮影 | 専用の矩形選択画面でドラッグ。選択した位置から写真がロープへ飛来 |
| 撮影中の Esc / 右クリック | 撮影をキャンセル。画像は保存しない |
| 画面全体 | ポインターがあるモニターをそのまま撮影 |
| 画面の上端に約0.5秒触れる | そのモニターに棚を表示 |
| 画像をクリック | PNG / DIB画像としてコピー |
| 画像をダブルクリック | 既定のアプリで開く |
| 長押し / 編集 | ペン、四角、切り抜き。動画ならトリミング |
| 画像を外へドラッグ | ファイルをアプリやフォルダーへコピー |
| 設定画面へドロップ / 画像を取り込む | ファイルのコピーを棚に追加 |
| 写真を右クリック | コピー、編集、開く、保存、固定、棚から外す |
| 写真に触れたときの × / 設定の「最後に外した画像を戻す」 | 棚から外す／復元 |
| 写真の上でホイール | 表示しきれない写真のページを切り替える |
| 通知領域のアイコン | 表示・撮影・設定・終了 |

クリップボード監視は初期状態でオフです。設定で有効にすると、画像だけのクリップボード変更を取り込みます。
テキスト・ファイルを含む混在データや、非公開／履歴除外を指定したデータは除外します。
同一の画像がSnipping Toolのクリップボードと監視フォルダーの両方に現れても、重複させません。

専用キャプチャは現在のデスクトップをすぐに固定表示し、ドラッグした矩形をその画像から切り出します。
撮影前に棚を隠す処理や固定の待ち時間はありません。棚が撮影範囲にあれば、そのまま画像に含まれます。
ドラッグの方向は自由です。クリックだけでは撮影せず、フォーカスが外れた場合もキャンセルします。
選択枠や暗幕は保存画像に入りません。クリップボードを経由せず、PNGと撮影位置を直接管理します。

初期状態ではWindowsの「ピクチャ」の `Screenshots` を監視します。OneDriveへのリダイレクトは既知のフォルダーAPIで解決します。
別の撮影先・動画保存先は「監視フォルダーを追加」で指定してください。
監視開始前からあったファイルは読み込まず、サイズと更新日時が安定した新規ファイルだけを取り込みます。
PNG、JPEG、BMP、GIF、WebP、およびMP4、MOV、MKV、WebMを受け付けます。動画の再生・変換はWindowsにインストールされたコーデックに依存します。

保存先は `%LOCALAPPDATA%\Snapline` です。設定と棚の一覧は `state.json`、メディアは `media` に保存します。
上限は通常30枚。固定した画像は自動的には外れません。棚から外したファイルもアプリの保存先に残り、復元できます。
原本の削除・移動は行いません。ドラッグ先がフォルダーでもコピーとして扱います。
マークアップや動画トリミングは新しいファイルとして保存します。ペイントでの編集は棚のコピーに反映されます。

## 実装

| macOS側 | Windows側 |
| --- | --- |
| SwiftUIの状態とビュー | `windows-reactor` 0.100のComponent / typed message / WinUIコントロール |
| AppKitのパネル・通知領域・ホットキー | 透過したWin32ホスト＋WinUIの設定・編集ウィンドウ、通知領域、ホットキー |
| Core Animation | Windows.UI.Composition のDesktopWindowTarget。ロープ、写真、個別の揺れ、スライド、撮影位置からの飛来 |
| システム撮影画像の領域メタデータ | 自前の矩形キャプチャ。仮想デスクトップの物理ピクセル座標と切り出し画像を一緒に保持 |
| NSPasteboard | Windowsクリップボード。自己コピーの再取り込みを抑止 |
| NSDraggingSession | OLE / ShellのIDataObjectによるファイルコピー |
| Markup | Rustで構築したWinUI編集画面。画像への描画と切り抜き |
| 動画トリミング | Windows.Media.Editing。変換はバックグラウンドで実行 |

XAMLファイル、WebView、Swiftランタイムは使っていません。
棚は背景パネルのない透明なデスクトップレイヤーです。元の150×104 ptの写真領域、画像の比率に沿った額縁、9×26 ptの金属クリップ、画面幅に応じたロープのたわみを使用します。
Direct2Dの描画サーフェスをCompositionで合成し、写真の間はネイティブのウィンドウ領域から除外しています。共有サーフェスの更新は描画領域にクリップします。
キャプチャはGDIのBitBltで取得します。飛来は650ミリ秒のcubic ease-in/outと上向きの弧で移動・縮小し、途中から額縁とクリップが現れます。
最後の120ミリ秒で棚の写真へクロスフェードします。開始位置・着地点は物理ピクセルで接続し、棚のDPI倍率と負のモニター座標を扱います。
外部ツールから監視フォルダーやクリップボード経由で取り込んだ画像には撮影位置がないため、従来の棚への追加表示を使います。
通常の棚には操作バーやファイル名を置かず、設定はトレイから開きます。`run-windows.ps1 -Test` の `--ui-test` は補助ウィンドウをComputer Useで選べるようにするため、検証中だけタスクバーへの表示とアクティブ化を許可します。
Reactorはプレビュー版なのでバージョンを固定しています。Borderに付けたReactorのコンテキストメニューで
実機クラッシュを確認したため、右クリックメニューとトレイメニューにはWindowsネイティブのポップアップを使用しています。

macOS固有のForce Touch、システムのスクリーンショット保存設定の引き継ぎ、ゴミ箱へのドラッグによる削除は移植対象外です。
Windows版のショートカットは上記2つに固定しています。UIは現在日本語です。
自動起動登録、HDRの色管理、画面録画そのものは実装していません。録画はSnipping Tool等で行い、その保存フォルダーを監視できます。
取り外し時の落下演出と背景をぼかすガラス材質は未実装です。現在の額縁は半透明の描画です。

## 検証

```powershell
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

動画の実機統合テストには3秒のH.264 / MP4を `test-data/fixtures/test-recording.mp4` に置きます。
FFmpegはテスト素材の生成にのみ使用でき、アプリには不要です。

```powershell
ffmpeg -f lavfi -i testsrc2=size=320x180:rate=24 -t 3 -c:v libx264 -pix_fmt yuv420p test-data/fixtures/test-recording.mp4
cargo test native_trim_preserves_source_and_sets_duration -- --ignored --nocapture
```

テストは監視ファイルの安定判定、保存と復元、固定項目の保持、重複取り込み防止、描画の境界処理、逆向き選択と負の画面座標での切り出しを検証します。
動画統合テストは元ファイルを維持したまま、0.5–2.0秒の範囲を1.5秒の動画へ書き出して検証します。

Computer Useで125%表示の実機を起動し、矩形の撮影、逆方向のドラッグ、Esc・右クリックでのキャンセル、クリックだけでは保存しないこと、飛来と着地を確認しています。
途中の描画を観察するときは `scripts/run-windows.ps1 -Test -SlowFlight` で飛来だけを10倍の時間にできます。通常起動では適用されません。
複数モニターをまたぐ座標変換は単体テスト済みですが、異なるDPIの複数モニターでの実機確認は未実施です。

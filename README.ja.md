# Snapline — Windows版

[Tendedero](https://github.com/alejandrobujan/tendedero)を基にした、Rust / WinUI 3のスクリーンショット用の棚です。
Windows版は [millfi/tendedero](https://github.com/millfi/tendedero) のフォークで開発しています。
上流のコードのMITライセンスと著作権表示を保持し、名前とアイコンは独自のものにしています。

## 起動とビルド

Windows 11 x64、Rust 1.98以降のMSVCツールチェーン、Visual StudioのC++ビルドツールが必要です。
初回ビルドではCargoとNuGetから依存関係を取得します。アプリの実行中にネットワーク通信は行いません。
配布はMSIXパッケージ、開発中の起動は自己完結ビルドを使います。同じソースから作りますが、
WinUIランタイムの入手方法だけが異なります。

### 開発用（自己完結ビルド）

```powershell
cargo build --locked --release
.\target\release\snapline.exe
```

`windows-reactor-setup` がWindows App Runtime 2.4を実行ファイルと同じフォルダーに配置します。
ポータブルに使う場合は、EXEだけを移動せず、同じフォルダーのDLL・PRI・言語フォルダー・アイコンも
一緒に置いてください。インストーラーや管理者権限は不要です。

開発用のDebugビルドの再起動は `scripts/run-windows.ps1`。このチェックアウトの実行ファイルを終了してから再ビルドします。
通常の利用では画像処理の速いReleaseビルドを使用してください。
`--data-dir <フォルダー>` は通常の保存先と分離した動作確認用です（指定したフォルダーが無ければ作成します）。

### 配布用（MSIX）

MSIXはWindows App Runtime 2（`Microsoft.WindowsAppRuntime.2`）を依存パッケージとして宣言し、
WinUIのランタイムを同梱しません。ほかのWinUIアプリと同じランタイムを共有するため、
配布物は約2 MB（自己完結ビルドの約62 MB）になります。

作成するには：

```powershell
.\scripts\build-windows.ps1
# build\Snapline.msix
```

- 前提：Windows 11 x64 と Windows App Runtime 2.4以降のフレームワークパッケージ。
  未インストールの端末には、Microsoftの配布する Windows App Runtime のインストーラーを先に入れます。
  アプリのインストールはそのままでは依存パッケージを自動では入れません。
- バージョンは `Cargo.toml` の `version` に第4要素 `.0` を足したものになります。
  同じバージョンを入れ直すときは一度削除するか、`Add-AppxPackage -ForceUpdateFromAnyVersion` を使います。
- 署名はオプションです。`-CertificatePath <pfx> -CertificatePassword <password>` でコード署名証明書を渡すと、
  AppxManifestの `Publisher` はその証明書の Subject に合わせて作られます。
  `-Publisher` / `-PackageName` / `-PublisherDisplayName` で未署名時の値を変えられます。
- 署名なしのMSIXは、開発者モードの端末で `Add-AppxPackage <msix> -AllowUnsigned` として動作確認できます。
- 自己署名で試す場合は `-SelfSigned` を使うと `build\Snapline.cer` も作成されます。この証明書は端末の
  信頼済みストア（管理者権限）へ入れてから `Add-AppxPackage <msix>` します。

動作確認は、署名せずに展開済みレイアウトを開発者モードで登録するのが最短です。

```powershell
.\scripts\build-windows.ps1 -Register
```

- 登録先がシステムドライブ以外（例：`A:`）のときは、内部でシステムドライブへレイアウトを複製してから登録します。
  ドライブが異なるだけで通知領域アイコンの登録がWindowsに拒否されるためです。
- `-Register` はビルド後、登録対象の実行中のSnaplineを停止して終了を待ち、既存登録を解除してからファイルを置き換えます。別のチェックアウトのSnaplineは停止しません。
- 起動は `%LOCALAPPDATA%\Microsoft\WindowsApps\snapline.exe`（アプリ実行エイリアス）から行えます。
  `--ui-test` と `--data-dir` もそのまま渡せます。
- `--features msix` のビルドはフレームワークパッケージからランタイムを解決するため、
  パッケージとして登録した状態でのみ起動します。`target\release\snapline.exe` を直接実行しても起動しません。

MSIX版の保存先は自己完結ビルドと同じ `%LOCALAPPDATA%\Snapline` です。パッケージはフルトラスト
（`mediumIL`）で動くため、ファイルはパッケージの仮想ストアに入らず、メディアと設定はアンインストール後も残ります。

## 使い方

| 操作 | 動作 |
| --- | --- |
| Ctrl+Alt+T | 棚を表示／非表示 |
| Ctrl+Alt+S / 範囲を撮影 | 専用の矩形選択画面でドラッグ。選択した位置から写真がロープへ飛来 |
| 撮影中の Esc / 右クリック | 撮影をキャンセル。画像は保存しない |
| 画面全体 | ポインターがあるモニターをそのまま撮影 |
| 画面の上端に約0.5秒触れる | そのモニターに棚を表示 |
| 画像をクリック | PNG / DIB画像としてコピー。動画は既定のアプリで開く |
| 画像をダブルクリック | 既定のアプリで開く |
| 長押し / 編集 | ペン、四角、切り抜き。動画ならトリミング |
| 画像を外へドラッグ | ファイルをアプリやフォルダーへコピー |
| 設定画面へドロップ / 画像を取り込む | ファイルのコピーを棚に追加 |
| 写真を右クリック | コピー、マークアップ、既定のアプリで開く、名前を付けて保存…、棚に固定／固定を解除、棚から外す |
| 写真に触れたときの × / 設定の「最後に外した画像を戻す」 | 棚から外す／復元 |
| 写真の上でホイール | 表示しきれない写真のページを切り替える |
| 通知領域のアイコン | 表示・撮影・設定・終了 |

クリップボード監視は初期状態でオフです。設定で有効にすると、画像だけのクリップボード変更を取り込みます。
テキスト・ファイルを含む混在データや、非公開／履歴除外を指定したデータは除外します。
同一の画像がSnipping Toolのクリップボードと監視フォルダーの両方に現れても、重複させません。

専用キャプチャは Windows.Graphics.Capture の最初のフレームを固定表示し、ドラッグした矩形をその画像から切り出します。
撮影前に棚を隠す処理や固定の待ち時間はありません。棚が撮影範囲にあれば、そのまま画像に含まれます。
ドラッグの方向は自由です。クリックだけでは撮影せず、フォーカスが外れた場合もキャンセルします。
選択枠や暗幕は保存画像に入りません。クリップボードを経由せず、PNGと撮影位置を直接管理します。

初期状態ではWindowsの「ピクチャ」の `Screenshots` を監視します。OneDriveへのリダイレクトは既知のフォルダーAPIで解決します。
別の撮影先・動画保存先は「監視フォルダーを追加」で指定してください。
監視開始前からあったファイルは読み込まず、サイズと更新日時が安定した新規ファイルだけを取り込みます。
PNG、JPEG、BMP、GIF、WebP、およびMP4、MOV、MKV、WebMを受け付けます。動画の再生・変換はWindowsにインストールされたコーデックに依存します。

保存先は `%LOCALAPPDATA%\Snapline` です。設定と棚の一覧は `state.json`、メディアは `media` に保存します。
上限は通常30枚。固定した画像は自動的には外れず、固定だけで上限を超える場合はそのまま保持します。棚から外したファイルもアプリの保存先に残り、戻せるのは最後に外した1枚です。
原本の削除・移動は行いません。ドラッグ先がフォルダーでもコピーとして扱います。
マークアップや動画トリミングは、保存場所（`media`）に新しいファイルとして書き出し、棚には別の1枚として入ります。ペイントでの編集は棚のコピーに反映されます。

## 実装

| macOS側 | Windows側 |
| --- | --- |
| SwiftUIの状態とビュー | `windows-reactor` 0.100のComponent / typed message / WinUIコントロール |
| AppKitのパネル・通知領域・ホットキー | 透過したWin32ホスト＋WinUIの設定・編集ウィンドウ、通知領域、ホットキー |
| Core Animation | Windows.UI.Composition のDesktopWindowTarget。ロープ、写真、個別の揺れ、スライド、撮影位置からの飛来 |
| システム撮影画像の領域メタデータ | 自前の矩形キャプチャ。仮想デスクトップの物理ピクセル座標と切り出し画像を一緒に保持 |
| NSPasteboard | Windowsクリップボード。自己コピーの再取り込みを抑止 |
| NSDraggingSession | OLE / ShellのIDataObjectによるファイルコピー |
| Markup | Rustで構築したWinUI編集画面。画像への描画と切り抜き |
| 動画トリミング | Windows.Media.Editing。変換はバックグラウンドで実行 |

XAMLファイル、WebView、Swiftランタイムは使っていません。
棚は背景パネルのない透明なデスクトップレイヤーです。写真領域は元の150×104 ptを基準に、倍率（小0.8／中1.0／大1.35）を掛けた最大 (150×倍率−14)×(104×倍率) pt、その外側に8 ptの額縁、上端に9×26 ptの金属クリップ、画面幅に応じたロープのたわみを使用します。1ページに並ぶ枚数はモニター幅と倍率から決まります。
Direct2Dの描画サーフェスをCompositionで合成し、描画範囲だけを重複しない矩形ホストへ表示します。写真の間には入力を受けるホストを置かず、背後のアプリを操作できます。共有サーフェスの更新は描画領域にクリップします。GDIの描画・領域APIは使いません。
キャプチャは Windows.Graphics.Capture でモニターごとのフレームを取得し、Direct3D 11 で読み戻して仮想デスクトップの物理座標で合成します。カーソルは含めません。取得中にシステムのキャプチャ枠が短時間表示される場合があります。
フレームを受け取るまでアプリは結果を待ち、3秒以内に届かない場合はエラーを表示します。飛来は650ミリ秒のcubic ease-in/outと上向きの弧で移動・縮小し、途中から額縁とクリップが現れます。
最後の120ミリ秒で棚の写真へクロスフェードします。開始位置・着地点は物理ピクセルで接続し、棚のDPI倍率と負のモニター座標を扱います。
外部ツールから監視フォルダーやクリップボード経由で取り込んだ画像には撮影位置がないため、従来の棚への追加表示を使います。
通常の棚には操作バーやファイル名を置かず、設定はトレイから開きます。設定画面は通常のタスクバーウィンドウです。`run-windows.ps1 -Test` の `--ui-test` は、検証中だけ棚のコントローラーと撮影オーバーレイのタスクバー表示・アクティブ化を許可します（`--slow-flight` を併用すると飛来が10倍の時間になります）。棚の画素は別の矩形ホスト群にあるため、表示の確認にはデスクトップ全体を見てください。
Reactorはプレビュー版なのでバージョンを固定しています。写真と通知領域の右クリックメニューは、
Reactorのメニュー機能を経由しないWinUIの `MenuFlyout` です。
最小行高19 DIP、トレイは幅132 DIP、写真は幅176 DIPに調整し、背景に `DesktopAcrylicBackdrop` を適用しています。
Windowsの透過効果や省電力などの設定によって、アクリルが単色表示に切り替わる場合があります。

ファイルの取り込み・監視フォルダーの選択・名前を付けて保存には、Windows App SDKの非同期Pickerを使います。
表示されるのはOS標準のファイルブラウザーです。選択中もUIスレッドは待機せず、撮影と重複したPickerの起動を抑止します。
起動エラーもWinUIで表示します。WinUI自体が起動できない場合は `%TEMP%\Snapline-startup-error.log` に記録します。
通知領域、ホットキー、HWNDとCompositionの接続、クリップボード、OLEドラッグなどのWin32／COM連携は残ります。

macOS固有のForce Touch、システムのスクリーンショット保存設定の引き継ぎ、ゴミ箱へのドラッグによる削除は移植対象外です。
Windows版のグローバルホットキーは上記2つに固定しています。UIは現在日本語です。
自動起動登録、HDRの色管理、画面録画そのものは実装していません。録画はSnipping Tool等で行い、その保存フォルダーを監視できます。
取り外し時の落下演出と棚の背景をぼかすガラス材質は未実装です。現在の額縁は半透明の描画です。

## 検証

```powershell
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

動画の実機統合テストには3秒のH.264 / MP4を `test-data/fixtures/test-recording.mp4` に置きます。
FFmpegはテスト素材の生成にのみ使用でき、アプリには不要です。

```powershell
ffmpeg -f lavfi -i testsrc2=size=320x180:rate=24 -t 3 -c:v libx264 -pix_fmt yuv420p test-data/fixtures/test-recording.mp4
cargo test native_trim_preserves_source_and_sets_duration -- --ignored --nocapture
```

Windows.Graphics.Capture の実機テストは、ロックされていないデスクトップで実行します。モニター、仮想デスクトップ、モニター内の矩形を3回ずつ取得し、寸法、不透明アルファ、画像が黒一色でないこと、取得と解放の繰り返しを検証します。実行中はシステムのキャプチャ枠が短時間表示される場合があります。

```powershell
cargo test --locked native_snapshot_reads_monitor_and_desktop -- --ignored --nocapture
```

テストは監視ファイルの安定判定、保存と復元、固定項目の保持、重複取り込み防止、描画の境界処理、逆向き選択と負の画面座標での切り出しを検証します。
矩形ホストのテストは、範囲の和集合・隙間・画面端のクリップ・半透明画素を二重描画しないことを検証します。
Pickerのテストはキャンセルと失敗の区別、および保存元と同じパスを選んでも元データを壊さないことを検証します。
動画統合テストは元ファイルを維持したまま、0.5–2.0秒の範囲を1.5秒の動画へ書き出して検証します。

Computer Useで125%表示の実機を起動し、矩形の撮影、逆方向のドラッグ、Esc・右クリックでのキャンセル、クリックだけでは保存しないこと、飛来と着地を確認しています。
途中の描画を観察するときは `scripts/run-windows.ps1 -Test -SlowFlight` で飛来だけを10倍の時間にできます。通常起動では適用されません。
複数モニターをまたぐ座標変換は単体テスト済みですが、異なるDPIの複数モニターでの実機確認は未実施です。

### MSIX版の実機確認

パッケージとして起動した状態で確認します。

```powershell
.\scripts\build-windows.ps1 -Register
& "$env:LOCALAPPDATA\Microsoft\WindowsApps\snapline.exe" --ui-test --data-dir .\test-data
```

| 確認項目 | 期待 |
| --- | --- |
| 起動 | WinUIの設定画面と棚（`Snapline — Clothesline`）が表示される |
| WinUIランタイム | `%ProgramFiles%\WindowsApps` の `Microsoft.WindowsAppRuntime.2` から読み込まれる（パッケージにDLLが入っていない） |
| 通知領域 | タスクトレイにSnaplineのアイコンが出る。開くとメニューが使える |
| 写真メニュー | コンパクトなアクリルのメニューからコピー・編集・開く・保存・固定／解除・取り外しが使える。Escとメニュー外クリックで閉じる |
| ファイル選択 | 複数の画像・動画の取り込み、フォルダー追加、名前を付けて保存が使える。キャンセルで設定や保存元が変わらない |
| 棚の入力と表示 | 写真間で背後をクリックでき、写真のクリック・長押し・ドラッグ・ホイール、ホバー表示、スライドと飛来が使える。別DPIのモニターへ表示先を移しても位置が合う |
| 保存先 | `--data-dir` のパスにそのまま書き込まれる（`%LOCALAPPDATA%` の下でもパッケージの仮想ストアに入らない） |
| 範囲撮影 | 前面に全画面のゲームなどがあると、Windows が取得を拒否して `アクセスが拒否されました` を返すことがある。通常のデスクトップで確認する |

`--features msix` で作った実行ファイルを `target\release` から直接起動すると、パッケージIDがないため起動しません。
これは仕様です。
